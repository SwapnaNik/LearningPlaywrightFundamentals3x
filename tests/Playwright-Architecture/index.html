Playwright Architecture

Overview

Playwright architecture is built on a modern client-server model that communicates directly with browser rendering engines over a single, persistent network connection.

Playwright supports major browser engines such as Chromium, Firefox and WebKit.

Core Components of Playwright Architecture

1. Test Code

The test code is written using languages such as JavaScript, TypeScript, Python, Java or .NET.

Example: 

const { test, expect } = require('@playwright/test');

test('Login test', async ({ page }) => {

    await page.goto('https://example.com');

    await page.locator('#username').fill('admin');

    await page.locator('#password').fill('password');

    await page.locator('#login').click();

});

Browser → Browser Context → Page → Locator

One of the most important concepts in Playwright is understanding the relationship between the Browser, Browser Context, Page and Locator.

1. Browser

The Browser represents the actual browser instance launched by Playwright.

For example, Playwright can launch Chromium, Firefox or WebKit. 

const browser = await chromium.launch();

2. Browser Context

A Browser Context is an isolated browser session inside the browser.

Each context has its own cookies, local storage, session storage and other browser state.

This allows multiple tests to run independently without sharing session data. 

const context = await browser.newContext();
Important: Browser Context is similar to an incognito-style isolated browser session.

3. Page

A Page represents a browser tab or window.

A browser context can contain multiple pages. 

const page = await context.newPage();

We use the Page object to navigate to URLs and interact with the web application. 

await page.goto('https://example.com');

4. Locator

A Locator is used to identify and interact with elements on a web page.

Examples include buttons, text boxes, links, checkboxes and other DOM elements. 

const username = page.locator('#username');

await username.fill('admin');

Playwright locators also provide automatic waiting and retry behavior, which makes tests more reliable.

Understanding the Relationship

Component What it represents Example
Browser Actual browser instance Chromium / Firefox / WebKit
Browser Context Isolated browser session Separate cookies and storage
Page Browser tab Login page / Home page
Locator Element identification Button / textbox / link

Why Browser Context is Important

Browser contexts provide test isolation.

For example, suppose we have two tests:

  • Test 1 → Login as User A
  • Test 2 → Login as User B

Each test can use a separate browser context so that cookies, sessions and authentication data do not interfere with each other. 

const context1 = await browser.newContext();
const page1 = await context1.newPage();

const context2 = await browser.newContext();
const page2 = await context2.newPage();

Key Takeaway

Understanding this hierarchy is essential for working with Playwright effectively.

  • Browser = browser instance
  • Browser Context = isolated session
  • Page = browser tab
  • Locator = identifies elements on the page
